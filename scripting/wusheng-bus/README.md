## 0.4.2 本次修复与检查

- 车辆连接优先使用实际全局WebSocket，兼容模块导出；支持字符串和Scripting原生Data消息，另兼容事件包装。旧测试只模拟模块导出和字符串，未覆盖手机的这些差异。该兼容缺陷已复现并通过回归检查，但还不能据此断言手机网络问题已经排除。
- 分开处理连接超时、已连接但无数据、数据格式、发送失败、连接关闭、网络/TLS错误，不再把所有失败折叠成同一句“暂不可用”。连接等待12秒、连上后等数据10秒，完成后清理定时器和连接。
- 设置新增“检查实时车辆连接”，只访问公开线路和车辆，不读取账号、不定位、不请求乘车码。只保存最小连接阶段、时间、消息计数、接口来源和标准网络错误码，不保存响应原文或错误原文。
- 车辆通道失败时仍返回线路站点及地图，标为位置未更新，保持可选候车站和换向；不会把连接失败当作没有车辆。
- [完整接口复核](../../docs/wusheng-api-inventory.md)：缓存版本39发现48个HTTP路径，实测站名搜索、站台线路、公告、定制班线、失物查询和包车查询成功。清单不代表这些新功能已经全部加入界面。

## 保留0.4.1的修复

- 修复实际车辆通道使用 `lat/lng`、旧版只识别 `latitude/longitude` 导致 GPS 坐标未采用的问题。两种字段均支持；不完整、非数值、越界与全零坐标仍按站点位置回退，不混用不同字段对。
- 有车辆已经驶过候车站时，显示“暂无待到站车辆”并保留该方向车辆的当前位置、距离、所在站和已过本站提示；不再把无待到站车辆误写成线路没有车辆。候车时间仍只计算当前方向尚未驶过的车辆。
- 已用 101 路真实上下行响应验证：两方向各49个站点，当前代码可从 `lat/lng` 识别可用 GPS 坐标。车辆数量随运行变化；手机地图显示和坐标系仍需真机验证。

- 最近站台的每条线路只显示一个方向，优先当前方向；该站只提供另一方向时显示实际可用方向，不伪造反向服务。页面提供切换线路、换向，点线路打开详情。

## 15秒与 iOS 限制

前台可执行15秒轮询。桌面组件只向 WidgetKit 提交15秒后的更新请求，实际刷新由 iOS 的预算和调度决定，**不能保证桌面每15秒运行**，也没有常驻后台定位服务。依据：[Apple 更新说明](https://developer.apple.com/documentation/widgetkit/keeping-a-widget-up-to-date)、[Scripting Widget 说明](https://scriptingapp.github.io/guide/Widget/Widget%20Quick%20Start)。

本版默认自动模式。旧版手动策略首次迁移为自动；原有关闭状态和通勤模式保留。可在设置改为“随前台”或通勤。前台每次数据更新只请求重绘，不强制绕过系统频率限制；余额自动查询最多约每五分钟一次，不跟随每轮公交请求重复查询。

地图连线仅为按站序连接的示意，不是道路级导航轨迹。真实车辆经纬度存在时显示坐标上报，否则标为站点上报；不把站台图钉冒充车辆精确GPS。实际坐标系及 iPhone 地图效果仍待设备验证。

## 安装与使用

1. 在 Scripting 导入本版，覆盖同名“武胜公交”并重新运行。底部应有五页，账号页“当前版本”应显示0.4.2。已有钥匙串登录与主题保留。
2. 登录仍沿用运营商组件：圈 X 更新公交抓取重写，微信小程序产生授权请求后，回账号页点“从 BoxJS 导入”。不用文件、不用给 BoxJS 另加应用订阅。
3. BoxJS 连接由脚本自动尝试已保存域名、boxjs.com 和 boxjs.net；验证失败不会覆盖原登录。抓取链接与检查入口在“登录与抓取”二级页。
4. 实时公交页自动使用真实定位查询最近站台。点线路查看地图、全部站点和车辆；切换方向后按该方向站点与实际位置确定候车站，没有位置时可手动点站选择，不把第一站伪称为最近站。
5. 桌面添加 Scripting 小组件并选择“武胜公交”，普通参数留空。小中大每页1/2/3路当前方向线路；点线路打开详情，底部为线路、乘车码、换向，定位自动更新。
6. 组件样式页先选尺寸再选布局，各尺寸单独保存；预览使用本机已有数据，不调用乘车码接口。叠放仍可填“叠放1”…“叠放10”，手动建立同尺寸叠放，各层页码与方向独立。

## 组件策略

默认自动策略：向系统提交15秒刷新请求，同时更新公交与定位；账户余额有独立约五分钟查询间隔。

通勤策略：按手机本地时间07:00–09:00、17:00–19:30自动更新，其他时间休眠。随前台策略平时仅读取本机已有数据，打开实时公交后共享前台更新。总开关关闭后显示关闭状态，只有显式唤醒才能恢复桌面联网。

休眠与关闭仅限制桌面自动查询，不影响手动取码、订单或前台实时公交。翻页与附近换向只使用已有各方向数据；固定线路换向只读查询新方向站点和车辆，按原站坐标或唯一同名站匹配候车站，不能匹配时不填错站。多个尺寸/叠放重绘共享短时本地保护，实际执行时间仍由 iOS 决定。

## 预计到站与车辆位置

仅在快照近期有效、车辆仍在本站之前且完整站距与正车速均可用时计算分钟数。车辆停驶/缺速、站距缺失、位置未更新时不假设平均车速。该方向没有车辆上报时显示“暂无车辆”；线路有车但没有待到本站的车辆时显示“暂无待到站车辆”，仍可点开位置。预计值不包含所有红灯、停站、拥堵因素。

进度条根据上报站序表示车辆前往本站的站点进度，不代表精确道路里程或套餐余量；数据不足时不画假进度。车辆米数区分“直线距本站”与“站距估算”，缺失时显示距离待更新。

最近站台仍使用真实设备定位。地图中自己的位置、站台、车辆分别标注；仅知道车辆所在站时，使用站点图钉并明确标记站点位置，不伪造车辆 GPS。

## 订单与乘车码

订单只读 `GetConsumedAndRechargeRecord`，乘车 `searchType=1`，充值 `searchType=0`，每页10条。只查询本机登录用户，先选择正确分支再规范化；金额仅用已核对的 `paymentAmount / 100`。保留未知状态码，不把未知状态强行当作成功。列表展示时间、金额、状态和线路，详情仅保留必要字段与卡/订单尾号；不保存完整响应或其中的 `qrCodeInfo`。

用户点击底部乘车码、桌面取码入口或页内刷新时，才请求一次新图及余额。普通启动实时公交、线路详情、其他页签、翻页、订单查询均不取码。离开取码页或20秒后隐藏图片；该时限为本页显示限制，不是官方有效期。迟到结果与切换账号的结果会丢弃。

取码参考坐标优先使用近期本机位置，其次已知站台，否则使用已实测成功的公共站坐标。参考坐标不作为用户实际位置，不影响附近公交的真实定位。码图仅保存在页面内存，不主动写入文件、Keychain、Storage或桌面快照。未知格式报错，不生成替代码。
